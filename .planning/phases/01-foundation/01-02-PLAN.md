Create two modules for CLI-to-Unity communication. Follow existing codebase conventions: named exports, camelCase functions, PascalCase interfaces, `.js` extension in imports for NodeNext module resolution.

**connection.ts** -- Unity instance discovery and validation:

```typescript
import * as fs from 'fs';
import * as path from 'path';
```

- Export `GameKitError` class extending `Error` with a `code: string` property. Constructor takes `(code: string, message: string)`, sets `this.name = 'GameKitError'`.

- Export `ServerInfo` interface: `{ port: number; pid: number; unityVersion: string; projectPath: string; startedAt: string; }`

- Export `isProcessRunning(pid: number): boolean` -- try `process.kill(pid, 0)`, return true. Catch returns false. This is the cross-platform way to check PID liveness.

- Export `readServerInfo(projectPath: string): ServerInfo` -- reads `.gamekit/server.json` from project path. If file doesn't exist, throw `GameKitError('UNITY_NOT_RUNNING', 'Unity is not running.\n\nOpen your project in Unity, then try again.\nThe gamekit plugin starts automatically when Unity opens.')`. Parse JSON into `ServerInfo`. Validate PID with `isProcessRunning(info.pid)` -- if dead, delete the stale port file and throw `GameKitError('UNITY_NOT_RUNNING', 'Unity is no longer running (stale port file removed).\n\nReopen Unity and try again.')`.

- Export `async healthCheck(port: number, timeoutMs: number = 3000): Promise<boolean>` -- fetch `http://localhost:${port}/api/health` with `AbortSignal.timeout(timeoutMs)`. Parse JSON, return `body.success === true`. Catch any error and return `false`.

- Export `async getConnection(projectPath: string): Promise<ServerInfo>` -- call `readServerInfo(projectPath)` to get info, then `healthCheck(info.port)`. If not healthy, throw `GameKitError('UNITY_NOT_RESPONDING', 'Unity is running but the gamekit plugin is not responding.\n\nTry restarting Unity, or run: gamekit doctor')`. Return info on success.

**bridge.ts** -- HTTP client for Unity communication:

```typescript
import { GameKitError } from './connection.js';
```

- Export `ApiResponse<T>` interface: `{ success: boolean; data: T | null; error: { code: string; message: string } | null; }`

- Export `async request<T>(port: number, method: string, path: string, body?: unknown, timeoutMs: number = 10000): Promise<T>`:
  - Construct URL: `http://localhost:${port}/api${path}`
  - Call `fetch(url, { method, headers: body ? { 'Content-Type': 'application/json' } : undefined, body: body ? JSON.stringify(body) : undefined, signal: AbortSignal.timeout(timeoutMs) })`
  - Parse response as `ApiResponse<T>`
  - If `!envelope.success`, throw `GameKitError(envelope.error?.code ?? 'UNKNOWN_ERROR', envelope.error?.message ?? 'Unknown error from Unity plugin')`
  - Return `envelope.data!`
  - Catch fetch errors: if `error.cause?.code === 'ECONNREFUSED'`, throw `GameKitError('UNITY_NOT_RUNNING', 'Cannot connect to Unity. Is the gamekit plugin running?\n\nTry: gamekit doctor')`. For timeout (`error.name === 'TimeoutError'`), throw `GameKitError('TIMEOUT', 'Request to Unity timed out. The editor may be busy.')`. For other errors, throw `GameKitError('CONNECTION_ERROR', 'Failed to communicate with Unity: ' + error.message)`.

Create the output formatting module that ensures consistent JSON-to-stdout and human-readable-to-stderr output across all gamekit commands. Follow existing codebase conventions.

**output.ts**:

```typescript
import chalk from 'chalk';
```

- Export `OutputOptions` interface: `{ json?: boolean; }` -- represents the `--json` CLI flag.

- Export `isJsonMode(options: OutputOptions): boolean` -- return `true` if `options.json === true` OR `!process.stdout.isTTY` (piped output defaults to JSON mode).

- Export `outputSuccess(data: unknown, options: OutputOptions): void` -- serialize `data` to JSON with 2-space indentation, write to `process.stdout.write(json + '\n')`. This is always JSON regardless of TTY mode -- the data goes to stdout for machine consumption.

- Export `outputError(code: string, message: string, exitCode: number = 1): never` -- write `JSON.stringify({ error: { code, message } })` + newline to stdout. If `process.stderr.isTTY`, also write `chalk.red('\nError: ' + message + '\n')` to stderr. Call `process.exit(exitCode)`.

- Export `log(message: string): void` -- human-readable status messages. Only write to stderr if `process.stderr.isTTY`. Uses `process.stderr.write(message + '\n')`. This is for progress messages that should not pollute stdout JSON output.

- Export `logSuccess(message: string): void` -- like `log` but uses `chalk.green('checkmark ' + message)`.

- Export `logWarning(message: string): void` -- like `log` but uses `chalk.yellow('! ' + message)`.

Note: The `outputError` function exits the process. This is intentional for CLI commands -- on error, output the error JSON and exit non-zero. Commands that want to handle errors without exiting should catch `GameKitError` themselves and call `outputSuccess` with error data.
