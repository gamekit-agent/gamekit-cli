<objective>
Build the Unity Editor plugin that runs an HTTP server inside the Unity Editor, enabling CLI-to-Unity communication over localhost.

Purpose: This is the server-side half of the HTTP bridge. Without it, no gamekit command can communicate with Unity. It must handle the three hardest Unity plugin challenges: main thread dispatch (Unity APIs are main-thread-only), domain reload survival (every C# edit kills all static state), and port management (multiple Unity instances must coexist).

Output: 7 C# files + 1 asmdef under `template/Editor/GameKit/` ready to be copied into Unity projects during `gamekit init`.
</objective>

Create the core Unity plugin infrastructure. All files use the `GameKit` namespace.

**GameKit.asmdef** -- Assembly definition file:
- Name: "GameKit", rootNamespace: "GameKit"
- includePlatforms: ["Editor"] only (this is an Editor-only plugin)
- No references, no unsafe code, autoReferenced true
- This ensures the plugin never compiles into player builds

**GameKitServer.cs** -- HTTP server lifecycle:
- Annotated with `[InitializeOnLoad]` so it restarts after every domain reload
- Static constructor registers: `AssemblyReloadEvents.beforeAssemblyReload` (stop server), `AssemblyReloadEvents.afterAssemblyReload` (no-op, restart happens via `[InitializeOnLoad]`), `EditorApplication.quitting` (stop + delete port file)
- Use `EditorApplication.delayCall` in static constructor to defer `StartServer()` -- avoids asset operation errors during early init
- `StartServer()`: calls `PortManager.FindAvailablePort(17580, 17589)`, creates `HttpListener`, adds prefix `http://localhost:{port}/`, sets `IgnoreWriteExceptions = true`, calls `Start()`, begins async listening via `BeginGetContext(OnRequestReceived, null)`, calls `PortManager.WritePortFile(port)`
- `StopServer()`: if listener is listening, call `Stop()`, `Close()`, set to null
- `OnBeforeReload()`: call `StopServer()` but do NOT delete port file (server restarts after reload)
- `OnEditorQuitting()`: call `StopServer()` + `PortManager.DeletePortFile()`
- `OnRequestReceived(IAsyncResult)`: guard for null/stopped listener, call `EndGetContext`, pass context to `RequestRouter.HandleRequest` via `MainThreadDispatcher.Invoke()`, handle `ObjectDisposedException` and `HttpListenerException` silently (expected on Stop()), re-register `BeginGetContext` in finally block if listener is still running
- Log `[GameKit] Server started on port {port}` on successful start
- Log `[GameKit] Could not find available port in range 17580-17589` on failure

**MainThreadDispatcher.cs** -- Thread-safe main thread dispatch:
- Static class with `[InitializeOnLoadMethod]` attribute (not `[InitializeOnLoad]` on class -- use the method-level attribute on a static Init method, or use a static constructor)
- Private `ConcurrentQueue<Action>` for the queue
- Register `EditorApplication.update += ProcessQueue` in static constructor
- `ProcessQueue()`: drain all actions from queue via `TryDequeue` in a while loop, execute each action
- `Invoke<T>(Func<T>)`: if on main thread (Thread.CurrentThread.ManagedThreadId == 1), execute directly. Otherwise, create `TaskCompletionSource<T>`, enqueue lambda that calls `SetResult` or `SetException`, return `tcs.Task.Result` (blocks HTTP thread until main thread executes)
- `Invoke(Action)`: same pattern but void return, using `TaskCompletionSource<bool>`
- Private `IsMainThread()` helper

**PortManager.cs** -- Port selection and port file I/O:
- Namespace: `GameKit.Utils`
- `FindAvailablePort(int start, int end)`: iterate port range, for each port create a temporary `HttpListener`, try to start it, if it succeeds then stop and return that port. If all fail, return -1. Catch `HttpListenerException` to continue to next port.
- `WritePortFile(int port)`: get project root via `Application.dataPath.Replace("/Assets", "")`, create `.gamekit/` directory, write `server.json` with JSON containing: port (int), pid (int via `Process.GetCurrentProcess().Id`), unityVersion (string via `Application.unityVersion`), projectPath (string), startedAt (ISO 8601 UTC string). Use `Newtonsoft.Json.JsonConvert.SerializeObject` with `Formatting.Indented`.
- `DeletePortFile()`: delete `.gamekit/server.json` if it exists
- `GetPortFilePath()`: private helper returning full path to `.gamekit/server.json`
- Use `[System.Serializable]` on the ServerInfo class for JSON serialization

Create the HTTP request handling layer. All files use the `GameKit` namespace (or sub-namespaces).

**ApiResponse.cs** (namespace `GameKit.Models`):
- `ApiResponse` class with fields: `bool success`, `object data`, `ApiError error`
- `ApiError` class with fields: `string code`, `string message`
- Static factory method `Success(object data)` returning `new ApiResponse { success = true, data = data, error = null }`
- Static factory method `Error(string code, string message)` returning `new ApiResponse { success = false, data = null, error = new ApiError { code = code, message = message } }`
- Use `[System.Serializable]` attribute or rely on Newtonsoft.Json conventions for serialization
- Fields should use lowercase property names for JSON output (use `[JsonProperty("success")]` attributes or configure serializer settings)

**RequestRouter.cs** (namespace `GameKit`):
- Static class `RequestRouter`
- `HandleRequest(HttpListenerContext context)`: extracts URL path and HTTP method from the context. Routes to appropriate handler based on path prefix:
  - `GET /api/health` -> `HealthHandler.Handle(context.Request)`
  - All other paths -> return 404 with `ApiResponse.Error("NOT_FOUND", "Endpoint not found: {path}")`
- After getting the `ApiResponse` from the handler, serialize it to JSON using `JsonConvert.SerializeObject(response)`, write bytes to `context.Response.OutputStream`, set `ContentType = "application/json"`, set appropriate status code (200 for success, 404 for not found, 500 for errors), close the response
- Wrap handler execution in try/catch; on exception return 500 with `ApiResponse.Error("INTERNAL_ERROR", exception.Message)`
- This is called FROM the main thread (via MainThreadDispatcher.Invoke in GameKitServer), so handlers can call Unity APIs directly

**HealthHandler.cs** (namespace `GameKit.Handlers`):
- Static class `HealthHandler`
- `Handle(HttpListenerRequest request)` returns `ApiResponse`:
  - Determine editor status: check `EditorApplication.isCompiling` -> "compiling", `EditorApplication.isPlaying && EditorApplication.isPaused` -> "paused", `EditorApplication.isPlaying` -> "playing", else -> "idle"
  - Return `ApiResponse.Success(new { status, unityVersion = Application.unityVersion, projectPath = Application.dataPath.Replace("/Assets", ""), projectName = Application.productName, platform = Application.platform.ToString() })`
  - Wrap in try/catch, return `ApiResponse.Error("HEALTH_CHECK_FAILED", ex.Message)` on exception

**Important:** The router dispatches requests that are already on the main thread. The threading boundary is in GameKitServer.OnRequestReceived, which calls `MainThreadDispatcher.Invoke(() => RequestRouter.HandleRequest(context))`. However, response writing (OutputStream) must happen BEFORE the HttpListenerContext goes out of scope. The pattern is: main thread executes handler, gets ApiResponse, writes response, closes stream -- all within the MainThreadDispatcher.Invoke call. Restructure accordingly: `MainThreadDispatcher.Invoke(() => { var response = route(context); writeResponse(context, response); })` so the full request-response cycle happens on the main thread in one shot.
