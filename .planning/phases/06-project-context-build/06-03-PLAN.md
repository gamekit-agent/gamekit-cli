Create `template/Editor/GameKit/Services/TestService.cs` as a static class in `GameKit.Services` namespace. This is the most architecturally complex service in Phase 6 due to async test execution and domain reload survival.

**Private nested class `TestResult`:**
- Fields: `string name`, `string fullName`, `string status`, `double duration`, `string message`, `string stackTrace`

**Static state:**
- `private static string _runStatus = "idle";` -- "idle", "running", "complete"
- `private static List<TestResult> _results = new List<TestResult>();`
- `private static readonly object _lock = new object();`

**[InitializeOnLoadMethod] Init():**
- `var api = ScriptableObject.CreateInstance<TestRunnerApi>();`
- `api.RegisterCallbacks(new TestCallbacks());`
- This re-registers callbacks after every domain reload (critical for PlayMode tests)

**`RunTests(string mode)`** (public static):
- Lock `_lock`, clear `_results`, set `_runStatus = "running"`, unlock
- `var api = ScriptableObject.CreateInstance<TestRunnerApi>();`
- Determine `TestMode`: if mode is "editmode" -> `TestMode.EditMode`; if "playmode" -> `TestMode.PlayMode`; else (default "both") -> `TestMode.EditMode | TestMode.PlayMode`
- **Important per research pitfall 5:** If mode is "both", run EditMode and PlayMode separately. First call `api.Execute(new ExecutionSettings(new Filter { testMode = TestMode.EditMode }))`. The TestCallbacks will handle collecting results. For PlayMode, we need a second Execute call, but since EditMode may still be running, the simplest reliable approach is: always use the combined mode flag (`TestMode.EditMode | TestMode.PlayMode`) and let Unity's TestRunner handle sequencing. The research notes this can sometimes skip PlayMode tests, but attempting manual sequencing in a static service adds significant complexity. Start with combined mode; if it proves unreliable, the service can be updated to sequential execution.
- `var filter = new Filter { testMode = testMode };`
- `api.Execute(new ExecutionSettings(filter));`

**`GetStatus()`** (public static) -- Returns `object`:
- Lock `_lock`, snapshot results with `_results.ToList()`, read `_runStatus`, unlock
- Count passed/failed/skipped from snapshot
- Return anonymous object: `{ status = runStatus, passed, failed, skipped, total = snapshot.Count, results = snapshot.Select(r => new { r.name, r.fullName, r.status, r.duration, r.message, r.stackTrace }) }`

**Private nested class `TestCallbacks : ICallbacks`:**
- `RunStarted(ITestAdaptor testsToRun)` -- no-op
- `RunFinished(ITestResultAdaptor result)` -- lock `_lock`, set `_runStatus = "complete"`, unlock
- `TestStarted(ITestAdaptor test)` -- no-op
- `TestFinished(ITestResultAdaptor result)` -- if `!result.HasChildren` (leaf test only): lock `_lock`, add `new TestResult { name = result.Name, fullName = result.FullName, status = result.TestStatus.ToString(), duration = result.Duration, message = result.Message, stackTrace = result.StackTrace }` to `_results`, unlock

Required usings: `System.Collections.Generic`, `System.Linq`, `UnityEditor`, `UnityEditor.TestTools.TestRunner.Api`, `UnityEngine`

**Note on TestRunnerApi availability:** The Test Framework package (`com.unity.test-framework`) is included by default in Unity 2019.2+. If a project has removed it, the service won't compile. This is acceptable -- the package is a standard Unity dependency. No conditional compilation needed.

Create `template/Editor/GameKit/Handlers/TestHandler.cs` in `GameKit.Handlers` namespace:

- **`HandleRun(HttpListenerRequest request)`** -- reads JSON body. Extracts `mode` (string, optional, defaults to "both"). Validates mode is one of "editmode", "playmode", "both" (case-insensitive, toLower). If invalid, return `ApiResponse.Error("INVALID_REQUEST", "Invalid mode. Use 'editmode', 'playmode', or 'both'.")`. Call `TestService.RunTests(mode)`. Return `ApiResponse.Success(new { status = "started", mode })`.

- **`HandleStatus(HttpListenerRequest request)`** -- call `TestService.GetStatus()`, return `ApiResponse.Success(result)`.

Required usings: `System`, `System.IO`, `System.Net`, `GameKit.Models`, `GameKit.Services`, `Newtonsoft.Json.Linq`

Update `template/Editor/GameKit/RequestRouter.cs` to add two routes (before 404 fallback):
- `POST /api/test/run` -> `TestHandler.HandleRun(context.Request)`
- `GET /api/test/status` -> `TestHandler.HandleStatus(context.Request)`

Single command `program.command('test').description('Run Unity Test Framework tests')` with:
- `.option('--editmode', 'Run only EditMode tests')`
- `.option('--playmode', 'Run only PlayMode tests')`

Action:
- Determine mode: if `opts.editmode` -> "editmode"; if `opts.playmode` -> "playmode"; else -> "both"
- `const info = await getConnection(process.cwd());`
- `log('Starting test run (mode: ' + mode + ')...')`
- Start test run: `await request(info.port, 'POST', '/test/run', { mode }, 30000);` -- 30s timeout for starting
- Poll for completion with a loop:
  ```typescript
  let status: TestStatus;
  do {
    await new Promise(r => setTimeout(r, 1000)); // 1-second poll interval
    status = await request<TestStatus>(info.port, 'GET', '/test/status', undefined, 30000);
  } while (status.status === 'running');
  ```
- `outputSuccess(status, globalOpts);`
- Human-readable output to stderr:
  - `logSuccess('Tests complete: ' + status.passed + ' passed, ' + status.failed + ' failed, ' + status.skipped + ' skipped')`
  - If `status.failed > 0`: iterate `status.results`, for each result where `result.status === 'Failed'`, log `'  FAIL: ' + result.fullName` and if `result.message`, log `'    ' + result.message`
  - If `status.failed > 0`: `process.exit(1)` after outputSuccess (non-zero exit on test failure)
